# 미해결 사항

작업 중 해결하지 못했거나 뒤로 미룬 항목을 기록한다. 해결하면 항목을 지우고 커밋 메시지에 남긴다.
요구사항 ID·실측은 [SPEC.md](SPEC.md) 참조.

## M2 TXT 뷰어 (2026-11-21)

### 성능

#### U-01. 컬러 이모지가 많은 문서의 스크롤 프레임 초과 (NFR-P07, SPEC Q11)
- **현상:** 7줄마다 컬러 이모지가 있는 `testdata/out/utf8.txt`의 스크롤 프레임 시간이 p50 11ms · p95 14ms · 최대 22ms로 나왔다. 600프레임 중 5–16프레임이 16ms를 넘었다.
- **근거:** 같은 내용에서 이모지만 뺀 `cp949.txt`는 p50 3.9ms · 초과 0이다. 소프트웨어 D2D 렌더 타깃이 컬러 글리프(`D2D1_DRAW_TEXT_OPTIONS_ENABLE_COLOR_FONT`)를 그리는 비용으로 보인다.
- **후보:** 행 단위 비트맵 캐시를 두거나, 이모지를 흑백 글리프로 그린다(컬러 옵션 끄기). GPU 렌더 타깃은 Q8 결정과 충돌한다. M4에서 재검토한다.

#### U-02. 1GB 스크롤 중 최대 Private Bytes 45.6MB
- **현상:** 1GB 파일을 처음부터 끝까지 스크롤하는 동안 최대 Private Bytes가 45.6MB였다. 열린 직후는 27.6MB, 색인이 끝난 뒤는 19.7MB다.
- **확인한 것:** 텍스트 레이아웃 캐시 예산(`LAYOUT_BUDGET`)을 1M → 128K 단위로 줄여도 값이 같아서 캐시가 원인은 아니다. 줄 색인 크기는 약 90KB다.
- **할 일:** DirectWrite·D2D 내부 캐시나 힙 단편화를 의심한다. 스크롤 중 메모리를 시간에 따라 표본 추출하고 VMMap 등으로 내역을 확인해야 한다. NFR-P04 목표(열 때 +30MB 이하)는 충족했다.

#### U-03. 비 UTF-8 문서의 찾기 속도
- **현상:** UTF-8 문서는 원시 바이트 경로로 1GB를 0.25–0.4초에 찾는다. CP949·UTF-16 등은 행마다 디코딩·소문자화하는 경로라 1GB에 약 5초가 걸린다. 검색어에 대소문자 변형이 ASCII 밖에도 있는 경우(예: `äö`, 켈빈 기호 때문에 `k`가 들어간 단어)는 UTF-8이어도 이 느린 경로를 쓴다.
- **후보:** 검색어를 문서 인코딩으로 변환해 바이트 경로를 확장한다. 단 DBCS는 ASCII 바이트가 둘째 바이트로 나올 수 있어 후보마다 글자 경계를 검증해야 한다. 그 밖에 블록 단위 병렬 처리, `find_in`의 SIMD화가 있다. 백그라운드 작업이고 진행률·취소를 지원하므로 급하지 않다.

### 기능

#### U-04. 매핑된 파일을 다른 프로그램이 저장하지 못할 수 있음 (FR-V06, SPEC §4.5 mmap 주의) — M4에서 일부 해결
- **해결한 것:** 파일 감시로 변경 이벤트를 받으면 매핑을 즉시 놓고 다시 읽으며 위치를 유지한다(임시변경 T-13). 덧붙이기(로그)·같은 크기 덮어쓰기는 이벤트가 오므로 반영된다.
- **남은 것:** 크기를 줄이며 저장하는 편집기는 첫 저장 자체가 `ERROR_USER_MAPPED_FILE`로 실패해 이벤트가 오지 않는다. 근본 해결은 매핑 대신 구간 읽기(파일 핸들 + 청크 캐시)다. 기준은 설정 `[text] mmap_threshold_mb`로 올릴 수 있다.

#### U-05. 긴 줄을 나눈 행 경계에 걸친 검색어를 찾지 못함 (FR-T06, FR-V04)
- **현상:** 4KB(`MAX_ROW_BYTES`)를 넘는 줄은 표시용 행으로 나눈다. 찾기는 행 단위라서 나눈 경계에 걸친 일치는 놓친다. 줄바꿈을 넘는 일치도 찾지 않는데, 이쪽은 의도한 동작이다.
- **후보:** 같은 논리 줄의 다음 행 앞부분(검색어 길이 − 1)을 이어 붙여 비교한다. 이때 결과 범위가 두 행에 걸치므로 `Hit`가 행 두 개를 표현할 수 있어야 한다.

#### U-06. 긴 줄 분할 위치가 자동 줄바꿈과 무관하게 보임
- **현상:** 줄바꿈을 켠 상태에서 5MB 한 줄을 보면, 4KB 행 경계마다 단어 중간이라도 줄이 바뀐다(예: `function f(a,b){` ↵ `return …`).
- **후보:** 행 경계를 단어 경계(공백·구두점)로 당기거나, 이어지는 행이면 바로 앞 행의 마지막 시각 줄과 이어서 배치한다.

#### U-07. 인코딩 수동 지정 미구현 (FR-T07, P1)
- 상태 표시줄을 클릭해 인코딩을 고르고 파일별로 기억하는 기능이다. 감지가 틀렸을 때 돌이킬 방법이 지금은 없다. 세션의 `FilePos`에 인코딩 필드를 추가해야 한다.

#### U-08. 줄 번호 표시 미구현 (FR-T08, P1)
- 줄 색인으로 화면 맨 위 행의 줄 번호는 구할 수 있다. 나머지는 거기서 행을 따라 세면 된다. 색인이 끝나기 전에는 표시하지 않거나 상대 번호로 보여 줄지 정해야 한다.

#### U-09. TXT 줄 번호 설정 (FR-T08) — 나머지는 M4에서 해결
- 글꼴·크기·탭 폭·줄바꿈 기본값·mmap 기준은 설정 `[text]`로 옮겼고, 자동 줄바꿈은 파일별로 세션에 기억한다. `line_numbers`는 U-08 구현 전이라 읽기만 한다.

#### U-10. 선택 편의 기능 없음 (FR-V05 보강)
- 더블클릭 단어 선택, 세 번 클릭 줄 선택, 키보드 선택(Shift+화살표)이 없다.
- 드래그 중 창 밖으로 나가면 마우스가 움직일 때만 자동 스크롤된다. 마우스를 멈추면 스크롤도 멈춘다(타이머 없음).
- 복사 상한은 64MB다. 그보다 큰 선택은 복사하지 않고 상태 표시줄에 안내만 한다.

#### U-11. 스크롤바 위치가 근사값
- 색인 후 스크롤바는 줄 단위다. 그래서 자동 줄바꿈으로 여러 시각 줄이 된 긴 줄에서는 엄지 크기와 위치가 실제 높이와 맞지 않는다.
- 색인 전에는 바이트 비율이라, 색인이 끝나는 순간 엄지 위치가 약간 튈 수 있다.

### 검증

#### U-12. 자동 확인하지 못한 조작
- `perf/capture.ps1`은 메시지 주입으로 Ctrl 상태를 만들 수 없다. 그래서 Ctrl+C·Ctrl+A·Ctrl+G·Ctrl+Home/End·Ctrl +/-/0을 TXT에서 자동 확인하지 못했다(Ctrl+휠은 휠 플래그로 확인).
- 클립보드에 들어간 내용, 스크롤바 엄지 끌기(특히 색인 전 바이트 단위), 창 최소화 뒤 복원, DPI가 다른 모니터로 옮기기는 수동 확인이 필요하다.
- CP949 외의 레거시 인코딩(Shift_JIS, GBK, Big5, EUC-JP, windows-125x)은 단위 테스트의 글자 경계 계산만 있고, 실제 파일로 확인하지 않았다.

#### U-13. 퍼징 미실시 (SPEC §10, P2)
- 행 탐색(`prev_row`·`row_containing`)과 UTF-16 정렬·DBCS 글자 경계 계산은 손상된 입력에서 경계 조건이 많다. `cargo-fuzz`로 "정방향 행 목록 = 역방향 행 목록" 불변식을 검사하면 좋다.

## M3 MD 뷰어 (2026-11-21)

### 기능

#### U-14. SVG 이미지 미지원 (FR-M11, P1)
- WIC는 SVG를 디코딩하지 못한다. 지금은 "이미지를 표시할 수 없음" 자리표시자가 나온다. `resvg`(feature flag)로 래스터화하는 경로가 필요하다.

#### U-15. front matter를 볼 방법이 없음 (FR-M08, P1)
- YAML front matter는 파싱해 `FlowDoc.front_matter`에 보관하지만 항상 숨긴다. 접이식 메타데이터 블록(설정 또는 클릭으로 펼침)은 없다. Ctrl+U 원문 보기로만 볼 수 있다.

#### U-16. 큰 MD의 "렌더링" 버튼 대신 단축키 (FR-M06)
- 8MB(설정 `[markdown] render_size_limit_mb`)를 넘는 MD는 TXT 보기로 열고 상태 표시줄에 "큰 MD라 원문 표시 — Ctrl+U: 렌더링"이라고 안내한다. SPEC의 "렌더링 버튼"은 없다. 마우스로 누를 수 있는 안내 막대가 필요하면 찾기 막대(`bar.rs`) 자리에 띄우는 방법이 있다.
- 글꼴·크기·본문 최대 폭·이미지 캐시는 M4에서 설정으로 옮겼다. 코드 블록 글꼴(Consolas)만 고정이다.

#### U-17. 원문 ↔ 렌더링 전환 시 위치가 이어지지 않음 (FR-M09)
- 렌더링 보기의 위치는 (레이아웃 단위, 오프셋), 원문 보기는 (바이트 오프셋, 행 안 높이)라 서로 바꿀 수 없다. 섞이지 않도록 세션 `FilePos.view`("md"/"txt"/"pdf")로 구분했고, 전환하면 다른 보기에서 마지막으로 본 위치(없으면 처음)로 열린다.
- 후보: 파싱할 때 단위마다 원본 바이트 범위(pulldown-cmark `into_offset_iter`)를 기록해 두면 양방향으로 대응시킬 수 있다.

#### U-18. 트리 밖 문서 링크 (FR-M04)
- 뒤로/앞으로(MD 앵커·문서 간 링크 포함)는 M4에서 해결했다.
- 트리 루트 밖 문서로 가는 링크는 트리 선택 동기화 없이 바로 연다. 숨김·필터로 트리에 없는 파일도 같다.

#### U-19. MD 찾기의 한계 (FR-V04)
- UI 스레드에서 동기로 찾는다(6MB 문서 29ms). 렌더링 상한이 8MB라 지금은 괜찮지만, 상한을 올리면 TXT처럼 워커로 옮겨야 한다.
- 문단 경계를 넘는 일치(예: 강제 줄바꿈은 공백으로 보지만, 문단 사이·표 칸 사이)는 찾지 않는다. 목록 표식(•, 1.)은 찾기 대상이 아니다.

#### U-20. 선택 편의 기능 없음 (FR-V05, U-10과 같은 내용)
- 더블클릭 단어 선택, 세 번 클릭 문단 선택, Shift+화살표 선택이 없다. 끌어서 창 밖으로 나가면 마우스가 움직일 때만 자동 스크롤된다.
- 이미지는 선택·복사 대상이 아니다(인라인 이미지 자리는 복사할 때 빠진다).

### 성능·메모리

#### U-22. 큰 MD의 메모리 (G1)
- 6MB MD를 끝까지 스크롤하는 동안 최대 Private Bytes 60MB(1MB 문서 30MB, 빈 창 13MB). 문단 글을 UTF-16으로 통째로 들고 있고(`Content.paras`), 문단마다 서식·링크 벡터가 따로 있다.
- 후보: 원본 UTF-8을 한 번만 보관하고 문단은 범위만 가리키기, 서식 범위를 문서 전체 배열 하나로 합치기. 레이아웃 캐시는 화면 ±1 화면이라 원인이 아니다.

#### U-23. 이미지 크기 조회가 첫 화면을 늦출 수 있음 (NFR-P03)
- 레이아웃이 흔들리지 않도록 열 때 앞 128개 이미지의 크기를 읽는다(헤더만). 평소엔 이미지 7개에 13ms지만, 부팅 뒤 첫 실행은 WIC 코덱 로드 때문에 69ms가 더 걸렸다(첫 화면 145ms).
- 129번째 이후 이미지는 보일 때 크기를 알게 되어 그 아래 내용이 밀린다(화면 맨 위 기준이라 화면은 튀지 않음).
- 후보: 크기 조회를 첫 화면 뒤 워커 작업으로 미루고, 화면 위쪽 이미지부터 조회한다.

### 검증

#### U-24. 자동 확인하지 못한 MD 조작
- Ctrl+U(원문 ↔ 렌더링), Ctrl+C(클립보드 내용·표의 탭 구분), Ctrl+A, Ctrl+휠·Ctrl +/-/0 확대, Ctrl+Home/End는 메시지 주입으로 Ctrl 상태를 만들 수 없어 확인하지 못했다(U-12와 같은 제약).
- 외부 링크(기본 브라우저), `mailto:`, 미지원 파일 링크(탐색기에서 선택), DPI가 다른 모니터로 옮길 때 이미지 다시 디코딩, 창 최소화 뒤 복원은 수동 확인이 필요하다.
- WebP(OS 코덱), JPEG, 큰 사진 이미지는 표본에 없다. `gen_md.py`는 표준 라이브러리만으로 PNG·BMP·GIF를 만든다.

## M4 다듬기 (2026-11-21)

### 성능

#### U-25. 컬러 이모지 TXT 스크롤 (U-01, SPEC Q11) — 그대로
- M4 재측정도 p50 11ms · 최대 20ms · 16ms 초과 8 / 600프레임. 행 비트맵 캐시나 이모지 흑백 그리기는 하지 않았다.

### 기능

#### U-26. 로딩 진행 표시 (FR-V01)
- "200ms 넘게 걸릴 때만 진행 표시"가 없다. 지금은 열기 시작하자마자 상태 표시줄에 "여는 중…"을 쓴다.

#### U-27. 최근 문서 파싱 상태 유지 (§4.5, 설정 `[memory] keep_recent_documents`)
- 문서를 바꾸면 이전 문서는 바로 해제한다. 뒤로 가기도 다시 읽는다(작은 문서는 수십 ms). 설정 값은 읽기만 한다.

#### U-28. 키보드 포커스 이동·고대비
- Tab 키로 사이드바 ↔ 문서 ↔ 찾기 막대를 오가지 못한다(마우스·Ctrl+B로만). 고대비 모드에서 시스템 색을 쓰지 않는다(§6.4, P1).

#### U-29. 사이드바·트리 편의
- 사이드바 폭 끌기 중 문서 영역은 매번 다시 배치된다(큰 PDF에서 끌기가 무거울 수 있음).
- 파일 트리 이름 바꾸기·여러 항목 한꺼번에 삭제는 없다. 새 파일·새 폴더·한 항목 삭제만 있다(FR-F15·F16).
- 트리 가로 스크롤이 없다. 긴 이름은 말줄임(…)으로 자른다.

### 검증

#### U-30. 자동 확인하지 못한 M4 조작
- 시스템 테마 전환(WM_SETTINGCHANGE), 창 프로시저 패닉 복구 화면, 감시 이벤트 유실(Rescan)은 수동 확인이 필요하다.
- 사용자가 수동으로 확인함: Ctrl+B(사이드바), Ctrl+Shift+E(외부 편집기), Ctrl+,(설정 파일 열기), 사이드바 폭 끌기, 우클릭 메뉴.
- 확인한 것: 다크·라이트 테마(설정 파일 실행 중 변경 포함), 파일 트리·목차 탭, 링크 이동 후 Alt+← 뒤로(트리 동기화), 열린 TXT 내용 변경 자동 새로고침, 새 파일 트리 반영, 단일 인스턴스 넘겨주기, 1만 항목 폴더.

## M5 v1.0 (2026-11-21)

### 기능

#### U-31. 이미지 보기의 빠진 기능 (FR-I06·I07, P2)
- GIF 애니메이션은 첫 프레임만 보여 준다(상태 표시줄에 "프레임 N개 중 첫 프레임").
- 이미지 복사(Ctrl+C), 투명 부분 체크무늬 배경, ICC 색 프로필 적용이 없다. 투명 PNG는 테마 배경색 위에 그려져 어두운 그림이 다크 테마에서 잘 안 보일 수 있다.
- HEIC·AVIF·JPEG XL은 확장 코덱이 있어야 WIC가 읽으므로 등록하지 않았다. SVG는 U-14.

### 성능·메모리

#### U-33. 큰 이미지 확대 중 순간 메모리·속도
- 6000×4000 PNG를 실제 크기 이상으로 볼 때 Private Bytes는 32MB지만 최대 작업 집합이 74–82MB까지 올랐다(WIC 디코더·크기 조절기의 내부 버퍼로 보인다).
- PNG·GIF는 줄 단위 압축이라 그림 아래쪽 영역을 디코딩할 때마다 위쪽 줄을 처음부터 다시 푼다. 아주 큰 그림(수억 픽셀)은 확대해서 아래로 스크롤할수록 세부가 늦게 나온다. 진행 표시가 없고(U-26), 그동안은 기본 비트맵을 늘려 보여 준다.
- 후보: 타일 캐시(PDF처럼 512px 타일 LRU), 디코딩 취소 플래그.

## v1.1 편집·새 파일 (2026-11-22)

### 기능

#### U-34. 편집기 한계 (FR-E)
- 실행 취소는 EDIT 컨트롤의 1단계(Ctrl+Z)뿐이다. 다시 실행(Ctrl+Y)·찾기/바꾸기·줄 번호가 없다.
- 편집 중에 다른 프로그램이 파일을 바꿔도 알리지 않는다. 저장하면 편집기 내용으로 덮어쓴다.
- 설정 `[text] word_wrap`을 바꾸면 다음 편집부터 반영된다(EDIT 스타일이라 다시 만들어야 함). 글꼴·크기·탭 폭은 바로 반영된다.
- 편집기 위쪽 여백이 보기(16 DIP)보다 작다(EDIT는 좌우 여백만 설정).

#### U-35. 새 파일·폴더 입력 행
- 입력 중 폴더가 접히거나 트리가 다시 그려지면 입력 행은 그 폴더 바로 아래에 다시 끼워진다. 만들 폴더가 사라지면(감시로 삭제) 입력 행이 안 보인 채 남을 수 있다 — Esc로 취소.
- 만든 직후 선택은 폴더를 다시 읽은 뒤에 한다. 그 사이 다른 폴더 읽기가 먼저 끝나면 선택이 안 될 수 있다(파일은 만들어짐).

### 검증

#### U-36. 자동 확인하지 못한 편집 조작
- 확인한 것(메시지 주입 + 키 상태 공유): Ctrl+E 편집 → 입력 → Ctrl+S(CP949·LF 유지) → Esc, 메뉴 키로 새 파일(이름 입력 → 편집 → 저장)·새 폴더, 잘못된 이름 거부, CP949에 이모지 → UTF-8 저장 확인 상자, 수정 후 창 닫기 → 취소/저장 안 함.
- 확인한 것(삭제): Del → 아니오/예(휴지통), 편집 중 파일 Shift+Del(영구, 편집기 정리), 폴더 삭제.
- 수동 확인 필요: 휴지통에서 복원, 네트워크 드라이브 경고, 마우스 우클릭 빈 곳 메뉴, 입력칸 밖 클릭 시 확정, IME 한글 입력, 라이트 테마 색, DPI 변경 중 편집.
