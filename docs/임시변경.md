# 임시변경

작업 중 필요에 따라 기존 코드·스펙·도구를 바꾼 내용과 근거. 다음 세션이 점검하고, 이상이 없으면 지운다.

## M5 (v1.0, 2026-11-21)

### 스펙과 다르게 구현

| # | 변경 | 근거 | 점검할 것 |
|---|---|---|---|
| T-1 | §4.3의 `FormatHandler` trait 하나 대신 **기술자(`FormatInfo`, Win32 비의존) + 레지스트리 + `CustomFormat`/`CustomView`(leaf-win)** 로 나눴다. TXT·MD·PDF는 `OpenedDoc`으로 감싸지 않고 기존 `Content::Text/Md/Pdf`를 그대로 쓴다 | 포맷 크레이트는 Win32를 몰라야 하고(§4.1), 기존 세 보기를 trait 객체로 바꾸면 `app.rs` 전체를 다시 써야 한다. 새 포맷만 공통 경로를 타면 확장성 목표(G4)는 충족된다 | SPEC §4.3 구현 메모에 반영함 |
| T-2 | 이미지가 지원 형식이 되어 **트리에 이미지 파일이 기본으로 보인다** | 레지스트리가 트리 필터의 기준이라 자동으로 따라왔다 | 없음 — 사용자 확정(유지), SPEC FR-I01에 반영 |
| T-3 | 이미지 비트맵 예산은 새 설정 대신 **`[pdf] bitmap_cache_mb`(기본 64MB)** 를 쓴다. 기본 비트맵에 1/4, 확대 세부에 3/4 | 설정 파일 항목을 늘리지 않으려고. 의미가 같다(쪽/그림 비트맵 예산) | `[image]` 섹션을 따로 둘지 |
| T-4 | 이미지 "실제 크기"(배율 100%)는 **이미지 1px = 화면 1px** 이다. MD 안 이미지는 1px = 1DIP | 사진·스크린샷을 픽셀 그대로 보는 게 이미지 뷰어의 관례. MD는 본문 글자 크기에 맞춰야 한다 | 없음 — 사용자 확정(유지), SPEC FR-I02에 반영 |
| T-5 | 이미지 세션 위치: `FilePos.zoom`에 `"fit"` 또는 배율, `y_pt`에 세로 스크롤(DIP), **`offset`에 가로 스크롤(DIP)** 을 넣는다. `view = "image"` | 세션 형식을 바꾸지 않으려고 TXT용 `offset` 필드를 빌렸다 | 없음 |
| T-6 | 버전을 0.0.1 → **1.0.0** 으로 올렸다(워크스페이스) | M5 = v1.0 (§11). 패키지 이름·README·고지 파일이 이 버전을 쓴다 | 없음 |

### 기존 코드 변경

| # | 변경 | 근거 | 점검할 것 |
|---|---|---|---|
| T-7 | `leaf_core::SUPPORTED_EXTENSIONS` 상수 삭제. `is_supported_ext`는 설치된 레지스트리(전역 `OnceLock`)에 묻는다. 설치 전엔 아무것도 지원하지 않는다 | 확장자 목록이 한 곳(포맷 크레이트의 `FORMAT`)에만 있게 | `fs_tree` 테스트는 테스트용 레지스트리를 설치한다 |
| T-8 | `leaf-core`·`leaf-fmt-text`가 `leaf-doc`에 의존한다(`FormatInfo`) | 기술자 타입을 공유하려고. 의존 방향(§4.1)은 그대로 위 → `leaf-doc` | 없음 |
| T-9 | `app.rs` `open_file`이 확장자 `match` 대신 레지스트리의 `ViewKind`로 분기하고, 모르는 확장자는 워커에서 앞 1KB를 읽어 판별한다(`UiMsg::Sniffed`). `is_md_path`도 레지스트리를 쓴다 | U-21 | 없음 |
| T-10 | `mdload::factory`·`open_frame`을 `pub(crate)`로 | 이미지 보기가 같은 WIC 팩터리를 쓴다 | 없음 |
| T-11 | 잘린 PNG는 WIC가 오류 없이 읽은 데까지만 채우고 성공할 수 있다 → 오류 화면 대신 일부가 빈 그림이 나온다 | WIC 동작. 이미지가 아닌 파일은 오류 화면이 나온다 | 없음 |
